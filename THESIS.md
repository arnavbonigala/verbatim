# Thesis

AI agents are becoming the main consumers of model-server decode time, and agents write in a peculiar way: a large share of what they emit is text they have already read. An edit restates the lines it replaces, a fix rewrites a function with one line changed, and a tool call re-serializes a file as an escaped JSON string. Decode is memory-bound, so a server can check many tokens for nearly the cost of one, but only if something proposes the right tokens. Verbatim is that proposer. It indexes the agent's own session in the forms an agent actually copies in (line-number-stripped views, diff-prefixed lines, JSON-escaped strings, re-indented blocks), matches on text instead of tokens, and sizes every draft against a measured cost model of the hardware's verify kernel. Because the target model verifies every draft, output stays token-for-token identical to normal decoding, so operators get the speedup with no change in output. On a fanless laptop with llama.cpp it already makes edit turns write about twice as fast, and replaying thousands of real Claude 3.7 and OpenHands sessions shows the same pattern at scale. Since the drafter is engine-agnostic CPU code, the same component drops into vLLM or SGLang, where flatter verify costs on datacenter GPUs leave more of the copy-heavy share of agent traffic to claim.
